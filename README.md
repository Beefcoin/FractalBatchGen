# Automated Agglomerate Generation

Batch-generation workflow for creating fractal agglomerates with
different generation algorithms and exporting them as CSV and LIGGGHTS
`.sys` files.

## Requirements

A dedicated Conda environment is recommended.

### Python

-   Python \>= 3.12
-   NumPy
-   Matplotlib
-   PyVista
-   Meson
-   Ninja

Use the provided `environment.yml` to create and activate the environment:

``` bash
conda env create -f environment.yml
conda activate agglomerate-generation
```

### FracVAL / F2PY

FracVAL is written in Fortran and exposed to Python through a NumPy F2PY
extension. Building the extension additionally requires:

-   NumPy / F2PY
-   GNU Fortran compiler (`gfortran`)
-   C compiler / build tools
-   Meson
-   Ninja

On Ubuntu/Debian, the required system compilers can be installed with:

``` bash
sudo apt install build-essential gfortran
```

Check that the required tools are available:

``` bash
gcc --version
gfortran --version
python -m numpy.f2py --help
meson --version
ninja --version
```

## Building FracVAL

FracVAL has to be compiled for the Python version used by the active
environment.

Activate the Conda environment first:

``` bash
conda activate agglomerate-generation
```

Then build the F2PY extension from the FracVAL source directory:

``` bash
cd GenerationScripts/FracVALFortran

python -m numpy.f2py -c \
  Ctes.f90 random.f90 RAND_SAMPLE.f90 a_Random_PP.f90 \
  PCA_cca.f90 PCA_Subclusters_module.f90 \
  CCA_module.f90 fracval_wrapper.f90 \
  -m fracval \
  only: run_fracval init_ctes :
```

This creates a Python extension similar to:

``` text
fracval.cpython-312-x86_64-linux-gnu.so
```

Keep the compiled module inside `GenerationScripts/FracVALFortran/`.

> **Note:** The F2PY module is Python-version dependent. Rebuild it
> after changing the Python version or environment if the existing
> module is incompatible.

The build can be tested from the project root with:

``` bash
python -c "import sys; sys.path.insert(0, 'GenerationScripts/FracVALFortran'); import fracval; print(fracval.__file__)"
```

## Agglomerate Analysis

The automated generation workflow includes an optional analysis step for
calculating morphological properties of the generated agglomerates.

Analysis can be enabled in the JSON configuration:

```json
"analysis": {
    "enabled": true
}
```

If enabled, each successfully generated agglomerate is automatically passed
to the analysis framework after generation.

The analysis results of all enabled generation algorithms are collected in
a common CSV file:

```text
<output_directory>/analysis/analysis.csv
```

For example, a batch containing multiple generation algorithms produces an
output structure such as:

```text
generated/example/
├── Skorupski/
│   ├── *.csv
│   └── sys/
│       └── *.sys
├── FracVAL/
│   ├── *.csv
│   └── sys/
│       └── *.sys
├── Urbassek/
│   ├── *.csv
│   └── sys/
│       └── *.sys
└── analysis/
    └── analysis.csv
```

The resulting analysis table maps the generation algorithm and its input
parameters, such as `N`, `Df`, `kf`, and `seed`, to the calculated
morphological properties.

Using a common analysis table allows agglomerates generated by different
algorithms and parameter combinations to be compared directly.

### Available Analysis Modules

The following analysis modules are currently implemented:

- **Convex hull volume** – calculates the volume of the convex hull
  enclosing the agglomerate.
- **Porosity** – calculates the porosity of the agglomerate.
- **Packing fraction** – calculates the packing fraction of the
  agglomerate.

Analysis modules are located in:

```text
agglomerate_analysis/modules/
```

### Adding a New Analysis Module

New morphological properties can be added as independent Python modules
inside `agglomerate_analysis/modules/`.

A minimal analysis module has the following structure:

```python
NAME = "example property"

VERSION = "0.1"

DESCRIPTION = "Calculates an example morphological property."


def calculate(agglomerate):
    # Perform calculation here

    result = ...

    return result
```

The `calculate()` function receives an `Agglomerate` object containing
the particle positions and radii.

Modules may also define optional parameters:

```python
NAME = "example property"

VERSION = "0.1"

DESCRIPTION = "Calculates an example morphological property."


def calculate(agglomerate, parameter=8):
    # Perform calculation here

    result = ...

    return result
```

After creating the module, import it in `agglomerate_analysis/main.py`:

```python
from modules import example_property
```

and add it to `register_modules()`:

```python
def register_modules(registry):

    registry.register(
        convex_hull_volume,
        n_points=8
    )

    registry.register(
        porosity
    )

    registry.register(
        packing_fraction
    )

    registry.register(
        example_property,
        parameter=8
    )
```

Parameters supplied to `registry.register()` are passed to the module's
`calculate()` function. If no parameters are supplied, the default values
defined by the module are used.

The return value of each registered module is automatically added to the
common `analysis.csv` together with the generation algorithm, generation
parameters, and original input filename.


> [!NOTE]  
> The convex hull volume, porosity, and packing fraction modules currently use the same convex-hull implementation. However, the convex hull is calculated separately by each module, which may become computationally expensive for large agglomerates. This could be optimized in the future by reusing an already calculated convex-hull volume between analysis modules instead of recalculating it.

## Running

Make the launcher executable once:

``` bash
chmod +x generate.sh
```

Run one of the included test configurations:

``` bash
./generate.sh config/genTest_skorupski.json
./generate.sh config/genTest_urbassek.json
./generate.sh config/genTest_FracVAL.json
```

The batch runner reads the selected JSON configuration and generates the
Cartesian product of all list-valued parameters. Scalar parameters
remain constant for all corresponding runs.

If LIGGGHTS export is enabled in the configuration, every generated CSV
is automatically passed to `liggghtsWriter.py`, producing a matching
`.sys` file with the configured particle density.

Generated files are written to the `output_directory` specified in the
JSON configuration.

## Configuration

Generation parameters, parameter sweeps, random seeds, output
directories, LIGGGHTS export, and particle density are controlled
through the JSON configuration files.

See [`config/README.md`](configs/README.md) for the configuration
format and examples.
